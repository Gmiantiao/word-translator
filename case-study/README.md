# AI 给了五样东西,一样都没落地

> 一次个人用 AI 做产品的完整记录。
> 素材来自 2026-08-17 的协作会话逐轮原文与项目 git 历史,未做改写。
> 所有可复现的验证见 [`evidence.md`](./evidence.md)。

---

## 0. 两句话

**第 1 轮,AI 说:**

> 「看完代码,先跟你对齐一个事实,可能你自己都忘了自己做过:**你提的两个点子,其实都已经实现了。**」

**第 7 轮,我说:**

> 「我看到了,没有变化啊。。。」

这两句话隔了六轮。而它们说的是同一件事。

---

## 1. 作品

**拾词** —— 一个 Chrome 划词扩展。在任意网页选中文字,就地完成「翻译 · 问 AI · 收藏」,之后自动高亮、闪卡复习、一键回看原文。

| | |
|---|---|
| 代码 | 约 4500 行原生 JavaScript,零框架依赖 |
| 架构 | Manifest V3,5 个运行上下文(service worker / content script / popup / options / 管理页) |
| 周期 | 2026-06-12 → 2026-08-13,11 个 commit |
| 配套 | README、商店上架文案、4 张宣传页、4 张截图 |

首版极快:6 月 12 日 **15:59 首次提交 → 16:01 加 README → 16:08 加截图**,9 分钟内完成。此后两个月是持续迭代。

---

## 2. 现场

### 第 1 轮:我提想法

> 「关于这个插件,我有一个想法,其实这可以不单单只是一个翻译的插件。比如我划了一个中文的单词或者短句,我不理解的话,可以直接引用 ai 直接提问,而不是拷贝到大模型,省去了一个步骤。以及收藏划词之后,在插件页面又可以跳转到过往的页面……这个插件整体的功能或者说宣传点、叫法,是不是可以改修一下,你觉得呢」

### 第 1 轮:AI 的回应 —— 五样东西

**① 先纠正前提。** 它没有顺着做,而是先读了代码:

> 「你提的两个点子,其实都已经实现了。……所以这两个功能不是「要不要加」,而是「已经在,但没被当成主角」。」

**② 接住了我真正在问的问题。** 我问的是定位,它给了判断:

> 「翻译只是「划词」这个动作的第一个出口,不是全部。……把它往「划词 = 入口」重新定位。这是个更大的品类——阅读增强 / 浏览时随手处理文本的工具,而不是一个「词典插件」。」

**③ 具体建议。** 名字不要动、改副标题与功能排序、商店分类从「翻译」挪向「生产力 / 阅读工具」、第一张宣传图换成「选中 → 三件事」全景。

**④ 一个战略风险提示:**

> 「「省去拷贝到大模型」这个愿景目前卡在**用户要自己配 DeepSeek API Key**。对小白来说,配 Key 本身就是比「拷贝」更大的门槛。……这是这个定位能不能立住的关键,比改名字更重要。」

**⑤ 一个维护风险提示**(第 2 轮):

> 「现在 v2 和原版是两份代码副本——后续改代码时记得两边同步。」

**然后它问了一个问题:**

> 「要我把这两处代码改动也做了吗?还是先只保留文案这版?」

### 第 2 轮:我做了另一个选择

> 「ok 保留原版,然后复制修改重写一版」

这是一个合理的选择 —— 我想先拿到一版新定位的文案,原版留着做对照。AI 照做了,交付了 `README.v2.md`、`STORE_LISTING.v2.md`,随后又按我的要求生成了可加载的 `v2/` 目录。

**它问的那个问题,下一轮没有被回答。此后再也没有。**

### 第 3–6 轮:我的注意力去哪了

> 「打开文件位置」
> 「我需要一个可以直接在 chrome 里加载的文件」
> 「打开位置」
> 「不对啊,我没在 workspace 的文件夹里看见文件」

四轮。全在找一个目录。

而 AI 在文件系统里用绝对路径操作,说「已在 Finder 中打开」;我在自己熟悉的那一层找,说「我没看见」。**它指的是对的,我看的也是对的,我们不在同一个空间感里。**

### 第 7 轮:我回到了一开始的地方

> 「我看到了,没有变化啊。。。」

AI 回答:

> 「对,没变化是正常的——因为**我只改了文案,一行代码都没动**。」

我用了六轮,走到了 AI 在第一轮就站着的那个位置。

## 3. 结果

那版新定位的代码,真相是:

```bash
$ diff -rq . v2/ --exclude=manifest.json
（无输出 —— 所有代码逐字节相同）

$ diff manifest.json v2/manifest.json
< "name": "拾词",
> "name": "拾词 v2",
```

而这次协作在 git 里留下的痕迹是:

```bash
$ git log --oneline --since=2026-08-14 --until=2026-09-11
（无输出）
```

最后一次功能提交停在 2026-08-13,早于该会话。**从那天到本文档提交之前,仓库没有任何提交 —— 0 个 commit。**

那三个产物(两份新定位文档 + 一份代码副本)生成于 8 月 17 日,此后一直躺在本地工作区,直到本文档提交时才一并进入版本库。

## 4. 我学到的

### 一、价值是被接收的,不是被生产的

AI 在那次会话里给了五样东西:前提纠正、定位判断、执行建议、战略风险、维护风险。到会话结束,五样都没进入下一步。

问题不在 AI 那一侧 —— 它没有顺着我、没有糊弄、主动提示了风险、还两次问了下一步。问题在于:**AI 的产出要变成行动,中间需要一个由人完成的决定。而这个决定,在注意力被占满的那一刻,是不会发生的。**

产出量不是进展量。这一条对所有用 AI 做事的人都成立。

### 二、摩擦会吃掉带宽,而且吃掉的是最贵的那部分

「文件在哪个目录」是一个本可以一句话解决的问题。它花掉了四轮。

而它挤掉的,恰好是整段对话里唯一两个涉及"这事能不能成"的判断 —— API Key 门槛会决定「划词即问 AI」这个卖点是否立得住;双份代码会决定后续维护成本。**风险提示是最容易被摩擦淹没的东西**,因为它不解决当下的痛,只在未来收利息。

### 三、AI 说"已完成",和我确认"已完成",是两件事

AI 说的每一句都是真的:文件确实创建了,路径确实对,确实"已在 Finder 中打开"。但我验证的方式是**在另一个空间里用眼睛找**。

现在我改了做法:**用可执行的东西验收,而不是用看起来的样子验收。** 对这次的事,一句 `diff -rq . v2/` 就能替代那四轮往返。新目录、新文档、新版本号、新口号,全都太容易被生产,也都太容易被误认为进展。

## 5. 收尾

那三个文件现在就在这个仓库里。你可以自己跑一遍:

```bash
$ diff -rq . v2/ --exclude=manifest.json
（无输出 —— 逐字节相同）
```

我没有删掉它们,也没有把它们藏进某个分支。

**这次空转的现场,我把它一起发布了。**
